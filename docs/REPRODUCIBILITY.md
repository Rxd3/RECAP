# Reproducibility guide

Every command below comes from the owning member's runbook: [data/README.md](../data/README.md),
[HMM_RUNBOOK.md](../experiments/HMM_RUNBOOK.md), [CRF_EXPERIMENTS.md](CRF_EXPERIMENTS.md) and
[EVALUATION_PROTOCOL.md](EVALUATION_PROTOCOL.md), plus the final-push CLIs
(`recap run-ablations`, `recap build-word-clusters`, `recap tune-threshold`, `recap run-demo`). Run everything
from the repository root. `recap --help` lists the commands and `recap <command> --help` prints the full
options of one. The `scripts/` stubs run the same commands ([scripts/README.md](../scripts/README.md)); runs
made before the restructure (2026-11-01) were launched through them, and their manifests record those paths.

taggers ([EVALUATION_RESULTS_CRF.md](EVALUATION_RESULTS_CRF.md) §15) were trained by Member 2 outside it;

tested environment (CPython 3.13.1), including scikit-learn, SciPy and NumPy, through which the pickled
CRF models load; `python -m pip install -r requirements-lock.txt` recreates it.

**Hardware.** Training the improved CRF peaks at about 14.5 GB of RAM and takes 859–1,388 s per mode
on Member 3's machine; the basic CRF needs about 7 GB and 335–875 s. Prediction runs on a normal laptop: under 0.67 ms per
utterance for the improved CRF ([EVALUATION_RESULTS_CRF.md](EVALUATION_RESULTS_CRF.md), Provenance and
§10). An HMM fit takes about 9 s ([HMM_RESULTS.md](../experiments/HMM_RESULTS.md)).

## 2. Data

Rebuild release `sponspeech-m1-v2` from the official archive. First unpack the provenance
package (raw manifest and title snapshot) into the raw root, as [data/README.md](../data/README.md)
describes.

```bash
mkdir -p data/raw/sponspeech-gcs-generation-1716975130398953   # then unpack the provenance package here
recap prepare-data extract --raw-root data/raw/sponspeech-gcs-generation-1716975130398953
recap prepare-data build --raw-root data/raw/sponspeech-gcs-generation-1716975130398953 \
  --release-id sponspeech-m1-v2
python -m pytest
```

Then compare `data/processed/<release>/SHA256SUMS` and `data/splits/<release>/SHA256SUMS` with
the published copies. If the byte ranges can no longer be read, add `--archive <path>/sponspeech.tar.gz`
to `extract` (the full 63.5 GB archive). To use the team's archive instead of rebuilding:

```bash
shasum -a 256 -c <id>.SHA256SUMS
mkdir -p data/processed data/splits
tar -xzf <id>-processed.tar.gz -C data/processed
tar -xzf <id>-splits.tar.gz -C data/splits
(cd data/processed/<id> && shasum -a 256 -c SHA256SUMS)
(cd data/splits/<id> && shasum -a 256 -c SHA256SUMS)
```

The expected fingerprints are in [DATA_RELEASE_VALIDATION.md](DATA_RELEASE_VALIDATION.md).

## 5. CRF

Train one model (repeat for each mode and preset; the six runs and their hashes are in
[CRF_EXPERIMENTS.md](CRF_EXPERIMENTS.md) §7):

```powershell
.\.venv\Scripts\recap.exe train-crf train `
  --mode <A|B|C> `
  --input data/processed/sponspeech-m1-v2/mode_<A|B|C>/train.jsonl `
  --ids data/splits/sponspeech-m1-v2/default_train/mode_<A|B|C>.ids `
  --output experiments/runs/<run_dir>/<run_id>.joblib `
  --manifest-out experiments/runs/<run_dir>/<run_id>.manifest.json `
  --preset <basic|improved> `
  --algorithm lbfgs `
  --c1 0.1 --c2 0.1 --max-iterations 100 `
  --run-id <run_id> `
  --dataset-release sponspeech-m1-v2 `
  --policy-version m1-v2
```

Predict the primary validation list with the prediction manifest:

```powershell
.\.venv\Scripts\recap.exe train-crf predict `
  --model experiments/runs/<run_dir>/<run_id>.joblib `
  --input data/processed/sponspeech-m1-v2/mode_<A|B|C>/validation.jsonl `
  --ids data/splits/sponspeech-m1-v2/primary_eval/validation_mode_<A|B|C>.ids `
  --output experiments/runs/<run_dir>/<run_id>_val_predictions.jsonl `
  --manifest-out experiments/runs/<run_dir>/<run_id>_val_predictions.manifest.json
```

Test and test_amb use the same command, run once per frozen model: `--input .../test.jsonl`
with `--ids .../primary_eval/test_mode_<X>.ids`, and `--input .../test_amb.jsonl` with
`--ids .../primary_eval/test_amb_mode_<X>.ids`.

## 6. Scoring

```bash
mkdir -p results/tables
recap evaluate-models score --gold <processed>/mode_C/validation.jsonl \
    --ids <splits>/primary_eval/validation_mode_C.ids --predictions <model predictions>.jsonl \
    --masks <processed>/masks/case_joint/validation.jsonl --out results/tables/<run_id>.json
```

Modes A and B take the same command without `--masks`. Add `--bootstrap 1000` for the 95%
intervals (seed 2026 by default) and `--manifest <predictions>.manifest.json` to check the
prediction manifest. Paired comparisons and error examples:

```bash
recap evaluate-models compare --gold <gold> --ids <ids> --out <report>.json \
    --predictions-a <A>.jsonl --predictions-b <B>.jsonl --bootstrap 1000
recap evaluate-models errors --gold <gold> --ids <ids> --predictions <pred>.jsonl \
    --out <report>.json --per-pair 5
```

Per-class paired intervals (hypotheses H2–H4) add one `--class` per label to `compare`:

```bash
mkdir -p experiments/runs
recap evaluate-models compare --gold <processed>/mode_A/validation.jsonl \
    --ids <splits>/primary_eval/validation_mode_A.ids --predictions-a <A>.jsonl --predictions-b <B>.jsonl \
    --bootstrap 1000 --seed 2026 --class COMMA --class QUESTION --out experiments/runs/per_class.json
```

`score` never overwrites an output and never creates folders.

## 7. Ablations and threshold decoding (validation only)

```bash
mkdir -p experiments/runs
recap run-ablations --mode A --out experiments/runs/ablations_A --sample 50000 \
    --data-root data --release sponspeech-m1-v2
recap tune-threshold tune --model <model>.joblib --gold <processed>/mode_A/validation.jsonl \
    --ids <splits>/primary_eval/validation_mode_A.ids --grid 0.05:0.95:0.05 --out experiments/runs/tau_A.json
recap tune-threshold predict --model <model>.joblib --input <processed>/mode_A/test.jsonl \
    --ids <splits>/primary_eval/test_mode_A.ids --tau-file experiments/runs/tau_A.json \
    --out experiments/runs/crf_improved_tau_A_test.jsonl \
    --manifest-out experiments/runs/crf_improved_tau_A_test.manifest.json
```

Write every output under the ignored `experiments/runs/` (or `results/`): an untracked file at the
repository root makes a later HMM `tune` refuse to start, because it requires a clean working tree.
Modes B and C use `tau_B.json` and `tau_C.json` in the same folder.

`recap run-ablations` takes `--variants` to run a subset (`improved`,
`improved_minus_{window2,ngrams,question,clause,casing,position}`, `improved_plus_filler`,
`improved_plus_clusters` with `--cluster-map`, see section 11).
`--data-root` (default `data`) and `--release` (default `sponspeech-m1-v2`) locate the release.
It writes `DIR/mode_X/sample.ids` and one `DIR/mode_X/<variant>/validation.jsonl` per variant and
never reads test; score each file with `recap evaluate-models score` (section 6).
Mode C `tune` also takes `--masks <processed>/masks/case_joint/validation.jsonl`. τ is chosen on
validation; test is predicted once with the frozen τ.

**Sensitivity of the fixed CRF settings** ([EVALUATION_RESULTS_CRF.md](EVALUATION_RESULTS_CRF.md) §5):
retrain both presets on the 50k sample that `recap run-ablations` wrote, at each setting, then predict and
score validation only:

```bash
recap train-crf train --mode A --input <processed>/mode_A/train.jsonl \
    --ids experiments/runs/ablations_A/mode_A/sample.ids --preset improved \
    --c1 1.0 --c2 1.0 --max-iterations 300 --output experiments/runs/sensitivity/improved_c1.0_i300.joblib
recap train-crf predict --model experiments/runs/sensitivity/improved_c1.0_i300.joblib \
    --input <processed>/mode_A/validation.jsonl --ids <splits>/primary_eval/validation_mode_A.ids \
    --output experiments/runs/sensitivity/improved_c1.0_i300.jsonl
```

Repeat with `--preset basic` and c1 = c2 ∈ {0.01, 0.1, 1.0}, 100 or 300 iterations, then compare each
improved model with its basic twin (`recap evaluate-models compare --bootstrap 1000`).

## 8. Studies: joint vs punctuation-only (H1), leakage subsets and label granularity

```bash
mkdir -p experiments/runs
recap project-joint --predictions <mode C validation predictions>.jsonl \
    --gold <processed>/mode_A/validation.jsonl \
    --out experiments/runs/h1_A_from_C.jsonl --manifest-out experiments/runs/h1_A_from_C.manifest.json
recap evaluate-models compare --gold <processed>/mode_A/validation.jsonl \
    --ids <splits>/primary_eval/validation_mode_C.ids \
    --predictions-a <mode A validation predictions>.jsonl --predictions-b experiments/runs/h1_A_from_C.jsonl \
    --bootstrap 1000 --seed 2026 --out experiments/runs/h1_compare.json
recap build-leakage-subsets --mode A --split test --out experiments/runs/leakage_test_A
```

The leakage command writes `all.ids`, `kept.ids`, `excluded_train_video.ids`, `excluded_other_leak.ids`
and `excluded_quality.ids` with `counts.json`. For mode A test the counts are 17,695 / 12,668 / 2,706 /
2,130 / 191 ([EVALUATION_RESULTS_CRF.md](EVALUATION_RESULTS_CRF.md) §8). Score each list with
`recap evaluate-models score --ids`. The "all excluded" set (5,027 utterances for mode A test) is the
union of the three `excluded_*.ids` lists, for example
`cat excluded_train_video.ids excluded_other_leak.ids excluded_quality.ids > excluded_all.ids`
(the three lists are disjoint: 2,706 + 2,130 + 191 = 5,027).

**Label granularity, B→A** ([EVALUATION_RESULTS_CRF.md](EVALUATION_RESULTS_CRF.md) §11): project each mode B
model's validation predictions to mode A with the D5 mapping, then compare with its mode A twin:

```bash
recap project-joint --from B --predictions <mode B validation predictions>.jsonl \
    --gold <processed>/mode_A/validation.jsonl \
    --out experiments/runs/b_to_a.jsonl --manifest-out experiments/runs/b_to_a.manifest.json
recap evaluate-models compare --gold <processed>/mode_A/validation.jsonl \
    --ids <splits>/primary_eval/validation_mode_A.ids \
    --predictions-a <mode A validation predictions>.jsonl --predictions-b experiments/runs/b_to_a.jsonl \
    --bootstrap 1000 --seed 2026 --class COMMA --class PERIOD --class QUESTION --out experiments/runs/b_to_a_compare.json
```

## 10. Demo

Without `--text`, the demo prompts for input. A missing or unsupported model, or unusable text,
exits 1 with one `error:` line.

## 11. Comparison methods and robustness checks

All of these select settings on validation only and predict test once. Results:
[EVALUATION_RESULTS_CRF.md](EVALUATION_RESULTS_CRF.md).

**Hidden-event LM.** Train one model per (order, discount) of the grid, predict validation, score, and keep
the best setting on validation; then predict test once with it:

```bash
mkdir -p experiments/runs/hidden_event_lm
recap train-hidden-event-lm train --mode A --input <processed>/mode_A/train.jsonl \
    --ids <splits>/default_train/mode_A.ids --order <N> --discount <D> \
    --output experiments/runs/hidden_event_lm/A_o<N>_d<D>.json
recap train-hidden-event-lm predict --model experiments/runs/hidden_event_lm/A_o<N>_d<D>.json \
    --input <processed>/mode_A/validation.jsonl --ids <splits>/primary_eval/validation_mode_A.ids \
    --output experiments/runs/hidden_event_lm/A_o<N>_d<D>_validation.jsonl \
    --manifest-out experiments/runs/hidden_event_lm/A_o<N>_d<D>_validation.manifest.json
```

Score each prediction file with `recap evaluate-models score` (section 6; mode C needs `--masks`).

**Prior-adjusted threshold decoding (τ × γ).** `--train` and `--train-ids` add add-one label priors from
the training records and search γ together with τ:

```bash
mkdir -p experiments/runs
recap tune-threshold tune --model <model>.joblib --gold <processed>/mode_A/validation.jsonl \
    --ids <splits>/primary_eval/validation_mode_A.ids \
    --train <processed>/mode_A/train.jsonl --train-ids <splits>/default_train/mode_A.ids \
    --out experiments/runs/tau_gamma_A.json
```

`recap tune-threshold predict --tau-file experiments/runs/tau_gamma_A.json ...` (section 7) then applies the
frozen τ and γ.

**Gap classifier, question lookback and the factored casing pipeline** (validation, 50k training sample):

```bash
mkdir -p experiments/runs
recap run-ablations --mode A --out experiments/runs/gap_A --variants gap_improved
recap run-ablations --mode A --out experiments/runs/question2_A --variants improved,improved_plus_question2
recap run-ablations --mode C --out experiments/runs/factored_C --variants improved,case_improved,factored
```

The factored run writes `factored/validation.jsonl` (mode C labels) from a mode A CRF and a casing-only
CRF; score it with `--masks`. To join two existing prediction files yourself:

```bash
recap factor-predictions --punct <mode A predictions>.jsonl --case <CASE predictions>.jsonl \
    --gold <processed>/mode_C/validation.jsonl --out experiments/runs/factored_C.jsonl \
    --manifest-out experiments/runs/factored_C.manifest.json
```

**Word-cluster features** (`improved_plus_clusters`, validation, 50k training sample). Build one map per mode and
k from `default_train` only (`--out` must not exist; the map records the sha256 of the train-ids file, k, the seed and
the vocabulary size), train the variant with it, then compare with `improved` from the section 7 ablation run
(same seeded sample). `recap run-ablations` stops before training if the map's mode, release or train-ids sha256
does not match:

```bash
mkdir -p experiments/runs
recap build-word-clusters --mode <M> --k 100 --out experiments/runs/clusters/clusters_<M>_k100.json
recap build-word-clusters --mode <M> --k 300 --out experiments/runs/clusters/clusters_<M>_k300.json
recap run-ablations --mode <M> --sample 50000 --variants improved_plus_clusters \
    --cluster-map experiments/runs/clusters/clusters_<M>_k100.json --out experiments/runs/clusters_<M>_k100
recap evaluate-models compare --gold <processed>/mode_<M>/validation.jsonl \
    --ids <splits>/primary_eval/validation_mode_<M>.ids \
    --predictions-a experiments/runs/ablations_<M>/mode_<M>/improved/validation.jsonl \
    --predictions-b experiments/runs/clusters_<M>_k100/mode_<M>/improved_plus_clusters/validation.jsonl \
    --bootstrap 1000 --seed 2026 --class COMMA --class PERIOD --class QUESTION \
    --out experiments/runs/clusters_<M>_k100_compare.json
```

Repeat with k 300. `recap build-word-clusters` defaults to `--seed 2026 --min-count 5 --dims 100 --window 2`. In mode C, add `--masks <processed>/masks/case_joint/validation.jsonl` to `compare` and name joint labels
in quotes, for example `--class "COMMA|LOWER" --class "PERIOD|LOWER" --class "QUESTION|LOWER"`.

**Simulated ASR noise.** Write corrupted copies of the test inputs, then predict and score them with the
frozen models as in sections 5 and 6, using the noisy files, ID lists and masks:

```bash
mkdir -p experiments/runs
recap simulate-asr-noise --split test --wer 0.10 --seed 2026 --out experiments/runs/asr_wer10
recap simulate-asr-noise --edit-model v2 --split test --wer 0.10 --seed 2026 --out experiments/runs/asr_v2_wer10_s2026
```

The output folder (which must not exist) holds `mode_<A|B|C>/test.jsonl`, `test_mode_<M>.ids`, the
remapped `masks/test.jsonl` and `summary.json` with the achieved WER and edit counts. Repeat with
`--wer 0.05` and `--wer 0.15` (and `--seed 2027`, `--seed 2028` for multi-seed variance; see [ASR_NOISE_V2.md](ASR_NOISE_V2.md)).
